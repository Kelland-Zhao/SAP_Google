# 09 - 工单自动关闭（WorkOrderAutoClose）设计

日期：2026-11-02
状态：已确认（2026-11-02，可以开始实现）

## 1. 意图

在现有 SAP 数据自动化仓库里新增第 9 个项目：每天从 `Total_Workorder` 工作表里挑出「基本开始日期在运行日往前两周或更早、且不是 PM01」的工单，按当前状态自动完成：

1. 已释放但没有工时确认的 → 在 SAP 里做工时确认（IW48，批量）；
2. 已确认工时但没有技术完成的 → 在 SAP 里做技术完成（IW38，批量）；
3. 当天刚确认完工时的工单，紧接着并入同一轮技术完成。

目标：让这批工单最终同时具备 `TECO` 和 `CNF` 两个状态，即业务上所说的「被管理」。

## 2. 目标与非目标

### 目标

- 订单号来源固定为 `Total_Workorder` 的 C 列（`订单`），不靠 SAP 变式去猜。
- 每次运行只处理「基本开始日期在运行日往前 14 天或更早」的非 PM01 工单。
- 工时确认和技术完成都批量执行。
- 每张工单的执行结果打印到控制台，并追加写入同一 spreadsheet 的 `WorkOrderClose_Log` 工作表。
- 加入 `run_all.ps1`，排在第一次 `04` 之后；09 跑完再跑第二次 `04`，把新状态刷回 `Total_Workorder`。
- 重复运行安全：已经确认/已经技术完成的工单不会再次处理。

### 非目标

- 不处理 PM01 工单。
- 不处理基本开始日期不在窗口内的工单。
- 不修改 `Total_Workorder`、`MasterData` 等既有工作表；只向 `WorkOrderClose_Log` 追加日志。
- 不做「关单后回读 SAP 状态」的二次校验；以 SAP 返回的消息为准，最终状态由紧接着的第二次 04 反映到 Sheet。
- 不处理「已经 TECO 但没有 CNF」这类规则之外的异常单，只在控制台把它们列为异常。
- 不在 macOS 上运行；只支持公司 Windows 机器（SAP GUI Scripting + Python 3.11）。

## 3. 约束

- 运行环境：Windows + SAP GUI（脚本录制可用）+ Python 3.11。
- 依赖：`pywin32`、`gspread`、`google-auth`。不需要 Excel、pandas、openpyxl。
- SAP 登录：沿用 `sap_common.py` 的 `ensure_sap_running` / `open_session` / `close_session` / `close_sap`；不关闭别人正在用的 SAP 会话。
- Google 服务账号：仓库根目录的 `pyreadsp-b5b9c1909de6.json`（与 01/04/08 相同）。
- 控制台中文输出，代码风格与现有 `main.py` 一致。
- **数据新鲜度**：09 依赖 `Total_Workorder` 是 04 刚刷新过的。`run_all.ps1` 的顺序保证这一点；**单独手动运行 09 前必须先跑 04**，否则可能对已确认的工单重复做工时确认。09 启动时打印这条提醒。

## 4. 数据源与筛选

### 4.1 表格

- Spreadsheet：`Database_PM_Work_order`
  - URL：`https://docs.google.com/spreadsheets/d/1YzMGIQ2RcBlGIadWh5yfxlCmOpCuOBHpgKfEVz8_W98/edit`
- 工作表：`Total_Workorder`
- 表头在第 1 行，共 14 列：

| 列 | 表头 |
|---|---|
| A | 参考日期 |
| B | 通知 |
| C | 订单 |
| D | 功能位置 |
| E | 设备 |
| F | 描述 |
| G | 成本中心 |
| H | 系统状态 |
| I | ABC 标识 |
| J | 订单类型 |
| K | 基本开始日期 |
| L | 基本完成日期 |
| M | 实际开始日期 |
| N | 实际完成日期 |

按**表头名**定位列，不写死列号；缺少 `订单` / `系统状态` / `订单类型` / `基本开始日期` 任一列时，打印错误并以退出码 1 结束。

### 4.2 筛选规则

1. `订单`（C）为空 → 跳过并计数。
2. `订单类型`（J）等于 `PM01` → 排除；为空 → 跳过并计数。
3. `基本开始日期`（K）解析为日期；为空或无法解析 → 跳过并计数。
4. 只保留 `K <= 运行日 - 14 天` 的工单（含边界；没有下限，越早的工单也会进来）。
5. 按订单号去重，保留 Sheet 中第一次出现的顺序。
6. 状态解析：`系统状态`（H）按空白拆分后做**整词匹配**，避免 `CNF` 匹配到别的字符串。
7. 分组：
   - **组 A**（需要工时确认）：含 `REL`、不含 `CNF`、不含 `TECO`。
   - **组 B**（需要技术完成）：含 `REL`、含 `CNF`、不含 `TECO`。
   - **已管理**：同时含 `TECO` 和 `CNF` → 跳过。
   - 其他情况跳过，并在异常区打印，例如：
     - 含 `TECO` 但不含 `CNF`（已技术完成但未工时确认）；
     - 含 `CNF`、不含 `REL`、不含 `TECO`；
     - 含 `REL` 且含 `TECO`（正常数据里不应出现）。
8. **日志范围**：通过 J/K 初筛的每一单（非 PM01、K 已满 14 天），无论实际处理还是因状态跳过，都要在 `WorkOrderClose_Log` 留一行；PM01 和未满 14 天的行不写日志，只在控制台计数。

> 已用 `Total_Workorder` 的实际数据核对过：`REL` 和 `CNF` **可以共存**（存在 `REL CNF ...` 的行），所以组 B 的条件成立；`TECO` 行在抽样里没有 `REL`。

## 5. SAP 操作流程

两个事务都在同一个脚本会话里执行。每个事务开始前用 `/n<事务码>` 重置，避免上一次的屏幕状态干扰。

### 5.1 工时确认：IW48（批量）

录制来源：`工时确认IW48.txt`。组 A 为空则跳过 IW48；否则把所有组 A 订单号一次性提交：

1. `wnd[0]/tbar[0]/okcd` 输入 `/nIW48`，回车。
2. `wnd[0]/tbar[1]/btn[19].press()`（录制中的步骤，保持原样）。
3. 清空工作中心：按 `wnd[0]/usr/btn%_ARBPL_%_APP_%-VALU_PUSH`，在弹窗里按 `wnd[1]/tbar[0]/btn[16]`（全删），再按 `wnd[1]/tbar[0]/btn[8]`（复制/确认）。
4. 同样清空工厂 `%_WERKS_%`、订单类型 `%_AUART_%`。
5. 订单号：按 `wnd[0]/usr/btn%_AUFNR_%_APP_%-VALU_PUSH`；先按 `wnd[1]/tbar[0]/btn[16]` 清空；把所有组 A 订单号用换行拼成文本放进 Windows 剪贴板，按 `wnd[1]/tbar[0]/btn[24]`（自剪贴板上载），再按 `wnd[1]/tbar[0]/btn[8]`（复制/确认）。
6. 执行：`wnd[0]/tbar[1]/btn[8].press()`。
7. 轮询等待确认表出现（例如 `chkAFRD-AUERU[9,0]` 可访问），然后勾选第 0 行的三个复选框：
   - `wnd[0]/usr/tblSAPLCORUTABCDEF_3350/chkAFRD-AUERU[9,0]` → `selected = True`（最终确认）
   - `.../chkAFRD-AUSOR[10,0]` → `selected = True`（结清未清预留）
   - `.../chkAFRD-LEKNW[11,0]` → `selected = True`（没有剩余工作）
8. 按 `wnd[0]/tbar[1]/btn[9]`，再按 `wnd[0]/tbar[1]/btn[38]`，最后按 `wnd[0]/tbar[0]/btn[11]`（**保存**；用户确认最后一个是保存按钮）。
9. **紧接着在保存后读取** `wnd[0]/sbar` 的文本/消息类型判断结果；`E`/`A` 视为失败，`S`/`W` 视为成功（`W` 打印警告）。保存后不要再按返回键，直接进入后续步骤。
   - 如果 `sbar` 为空或消息类型无法识别：打印警告，**按整批失败处理**（组 A 全部不加入 TECO 名单，退出码 1）。下一次 04 刷新后，如果实际已确认成功，它们会进入组 B 做 TECO，不会重复确认。
10. 整批成功 → **所有组 A 订单**加入本轮 TECO 名单；整批失败 → 全部不加入，打印失败原因，组 B 的 TECO 仍照常执行。

补充：用户确认「勾第 0 行的三个框，再按后续按钮，就能让每一行都勾上」。批量提交后确认表里会列出所有订单的工序，脚本严格按这个顺序做，不自己遍历所有行。

### 5.2 技术完成：IW38（批量）

录制来源：`PM工单技术完成.txt`。TECO 名单 = 组 B + （如果 IW48 批次成功）全部组 A。名单为空则跳过。

1. `wnd[0]/tbar[0]/okcd` 输入 `/nIW38`，回车。
2. 按 `wnd[0]/usr/btn%_AUFNR_%_APP_%-VALU_PUSH` 打开订单多选。
3. 清空弹窗（`wnd[1]/tbar[0]/btn[16]`）。
4. 把 TECO 名单用换行拼成文本放进 Windows 剪贴板，按 `wnd[1]/tbar[0]/btn[24]`（自剪贴板上载），再按 `wnd[1]/tbar[0]/btn[8]`（复制/确认）。
   - 这个模式在 `02 - Critical_A_.../main.py` 已有现成实现，直接复用。
5. 在 `wnd[0]/usr/ctxtVARIANT` 填入 `/KEL`（格式/layout，用户明确要求保留）。
6. 执行：`wnd[0]/tbar[1]/btn[8].press()`。
7. 等待列表就绪。用户确认 `btn[5]` 和 `btn[45]` 中**有一个是全选按钮**；脚本按录制顺序依次按 `btn[5]` → `btn[45]`，不额外插入 Ctrl+A。
8. 弹窗按 `wnd[1]/usr/btnSPOP-VAROPTION1.press()` 确认。
9. 读取 `wnd[0]/sbar`，打印 SAP 返回的汇总消息；`E`/`A`、抛异常、或消息为空/无法识别，都视为整批失败，退出码 1。如果 SAP 明确返回「未选择订单」之类的消息，也视为整批失败。
10. 结束时打印本轮提交的订单号清单。

> 按钮顺序严格照录制；全选和执行这两个动作谁在前以录制为准，脚本不自己推断。

```

组 B（待技术完成）: 20 单
已管理（TECO+CNF）: 60 单
异常（已 TECO 无 CNF）: 3 单：...
[CNF] 批量提交 12 单: 5609259, 5611111, ...
[CNF] SAP 返回: ...
[CNF] 5609259 成功（整批结果）
```

- 控制台和 `WorkOrderClose_Log` 两份记录都要有；控制台是即时反馈，日志表是长期审计。
- 不写本地日志文件。
- 由 `run_all.ps1` 调用时，子进程的 `print` 会显示在控制台，但不会自动进 `run_all.log`（`run_all.log` 只记编排器自己打印的行）。这是现有行为，本期不改。

### 6.1 WorkOrderClose_Log 日志表

- 工作表已由用户手动创建（当前没有表头）；09 首次运行时如果 A1 为空，自动写入表头；如果工作表不存在，自动创建。
- **只追加，不覆盖历史**。
- 共 9 列：

| 列 | 字段 | 说明 |
|---|---|---|
| A | 执行时间 | `YYYY-MM-DD HH:MM:SS` |
| B | 运行日期 | 本次 09 的运行日 `YYYY-MM-DD` |
| C | 订单 | C 列原样（文本，保留前导零） |
| D | 订单类型 | J 列 |
| E | 基本开始日期 | K 列原样 |
| F | 处理前系统状态 | H 列原样 |
| G | 动作 | `工时确认` / `技术完成` / `跳过` |
| H | 结果 | `成功` / `失败` / `跳过` |
| I | 原因 / SAP 消息 | 失败原因、SAP 状态栏消息、跳过原因 |

- 组 A 每单一行「工时确认」，同一批的所有行共用批次的成功/失败和 SAP 消息；批次成功后如果进入本轮 TECO，再写一行「技术完成」。
- 组 B 每单一行「技术完成」。
- 状态被跳过的每单一行「跳过」，原因写具体（`已管理(TECO+CNF)`、`TECO无CNF`、`未释放` 等）。
- 批量 TECO 只能拿到整批的结果：成功时所有提交单记「成功」并附 SAP 汇总消息；整批失败时所有提交单记「失败」并附错误消息。
- 写日志用 gspread 的 `append_rows`，按文本原样写入，避免订单号被 Sheets 当数字吃掉。
- 日志写入失败：打印警告，**不改变退出码**（SAP 动作已经发生，不能因为日志失败就判定整次失败）。
- 日志写在与 `Total_Workorder` 相同的 spreadsheet：`Database_PM_Work_order`。

## 7. 退出码

沿用现有约定：

| 退出码 | 含义 |
|---|---|
| `0` | 成功，包括「没有候选工单」和「全部跳过」 |
| `1` | 读 Sheet 失败、SAP 会话失败、IW48 批量工时确认失败、或 IW38 批量技术完成失败 |

IW48 批次失败后不再把组 A 并入 TECO；组 B 的 TECO 仍照常执行。最后统一以 1 退出，便于 `run_all` 标记失败。

日志写入失败只打印警告，不改变退出码。

### 7.1 已知限制：上一年度及更早的行

当前 `04` 只重写当年数据，上一年度及更早的行原样保留。09 现在取 `K <= 运行日 - 14 天`（没有下限），因此上一年度及更早的工单都可能被选中，而它们在 Sheet 里的状态不会被 04 刷新，可能出现「已处理但 Sheet 仍显示未处理」的重复尝试。

用户已计划后续把 `04` 从「一个整年」改为「动态显示最近 365 天」，届时 Sheet 只保留最近一年，更早的行会消失，这个问题随之消失。在该改动完成前，09 不做特殊处理，只记录此限制。

## 10. 测试与验收

由于代码只能在公司 Windows 机器上跑，验收步骤：

1. **干跑**：`python "09 - WorkOrderAutoClose\main.py" --dry-run`
   - 只读 Sheet、打印筛选结果，不启动 SAP、不写任何东西。

4. **重复运行**：先跑一次 04 刷新，再跑一次 09，确认已处理的工单不再被选中（幂等）。
