# 10 - 工单取消技术完成（WorkOrderCancelTECO）设计

日期：2026-11-03
状态：待确认

## 1. 意图

新增第 10 个项目：把 `取消技术完成` 工作表里待处理的工单，**逐单**在 SAP 里撤销技术完成（TECO）。成功后在同行 B 列写 `Done`；失败原因写 C 列，B 列留空以便下次重跑。

这是一次性操作，不加入 `run_all.ps1`，不做定时。背景是 `09` 自动关单后，有一批工单被提前技术完成，用户把需要撤销的订单号维护在同一张 spreadsheet 的新工作表里。

## 2. 目标与非目标

### 目标

- 读取 `取消技术完成` 工作表：A 列订单号，B 列处理标记，C 列失败原因；**没有表头**，A1 就是第一单。
- 只处理 B 列为空的行；B 列已有内容（目前是 `Done`）的行跳过。
- 按 A 列从上到下的顺序，逐单执行 SAP 的 IW32「取消技术完成」流程。
- 每单保存后读 SAP 状态栏：成功才在 B 列写 `Done`，并清空 C 列。
- 失败时 B 列保持空、C 列写 `时间 | 原因`，继续处理下一单。
- 控制台打印每单进度、每单结果和最终汇总。
- 提供 `--dry-run` 和 `--only-orders`，便于先核对名单、再拿 1 单实跑验证。
- 退出码沿用仓库约定：全部成功或无事可做 → `0`；任意一单失败、读 Sheet 失败或 SAP 会话失败 → `1`。

### 非目标

- 不加入 `run_all.ps1`，不参与每日自动运行，不做任务计划。
- 不做批量提交：录制脚本是 IW32 逐单操作，用户也明确「只能逐条执行」。
- 不修改 `Total_Workorder`、`MasterData` 等其他工作表；只动 `取消技术完成` 的 B/C 两列。
- 不预先读 `Total_Workorder` 判断订单状态；名单是唯一依据，非 TECO 的单交给 SAP 报错并写 C 列。
- 不做保存后的状态回读（不额外开 IW33 核对）；以保存时 SAP 状态栏的消息为准。
- 不处理「取消以后又被 09 重新技术完成」的问题，见第 9 节。
- 不在 macOS 上运行；只支持公司 Windows 机器（SAP GUI Scripting + Python 3.11）。

### 4.1 表格

- Spreadsheet：`Database_PM_Work_order`
  - URL：`https://docs.google.com/spreadsheets/d/1YzMGIQ2RcBlGIadWh5yfxlCmOpCuOBHpgKfEVz8_W98/edit`
- 工作表：`取消技术完成`（Sheet ID `1684903716`）

| 列 | 用途 | 说明 |
|---|---|---|
| A | 订单号 | 数据从第 1 行开始，没有表头 |
| B | 处理标记 | 成功写 `Done`；其他非空值视为已处理并跳过 |
| C | 失败原因 | 脚本写 `YYYY-MM-DD HH:MM:SS | 原因`；成功后清空 |

现状（2026-11-03 核对）：A1:A59 共 59 单，B1 已是 `Done`，其余 58 单待处理；59 单在 `Total_Workorder` 里的状态全部是 `TECO CNF`。

### 4.2 处理规则

1. A 列为空 → 忽略该行，不碰 B/C。
2. B 列去空格后非空 → 视为已处理，跳过，不碰 C。
3. A 列去空格后作为订单号；按 A 列顺序处理。
4. 同一订单号出现多行：
   - 只向 SAP 提交一次；
   - 成功后，把该订单所有「B 列为空」的行的 B 列都写成 `Done`、C 列清空；
   - 失败后，这些行的 C 列都写同样的原因，B 列保持空。
5. `--only-orders` 在计划阶段过滤；不在指定集合里的行完全不动（连 B/C 都不碰）。
6. 不做表头检测。以后如果给 A1 加表头，它会被当成订单号送进 SAP 并在 C 列记一条失败；这是有意的简单做法，不是 bug。

## 5. SAP 操作流程

录制来源：`取消技术完成IW32.txt`（用户 2026-11-03 录制，单笔 IW32）。实现时把该文件复制进 `10 - WorkOrderCancelTECO/` 保存，与 09 保留录制文件的做法一致。

整个运行只开一个 SAP 会话；每单开始前用 `/nIW32` 重置，避免上一单的屏幕残留。

每单的步骤（严格按录制顺序）：

1. `wnd[0].maximize()`（会话开始时做一次即可）。
2. `wnd[0]/tbar[0]/okcd` 输入 `/nIW32`，`wnd[0].sendVKey(0)`。
3. 等待 `wnd[0]/usr/ctxtCAUFVD-AUFNR` 出现，写入订单号。
4. `wnd[0].sendVKey(0)`（回车，打开订单）。
5. 轮询等待菜单项 `wnd[0]/mbar/menu[0]/menu[8]/menu[2]/menu[1]` 出现（超时 30 秒），然后 `.select()`。
6. 弹窗处理（三个时点：回车打开订单后、菜单 `select()` 后、保存后）：
   - 读 `wnd[1]/sbar`（如果存在）的 `messageType` / `text`；读不到就记为「弹窗内容不可读」。
   - 弹窗消息类型是 `E` / `A`，或文本命中否定关键词 → **该单直接失败**：关闭弹窗、不再按保存，继续下一单。
   - 其他弹窗（确认框、信息框）→ `wnd[1].sendVKey(0)` 确认后继续。
7. 按 `wnd[0]/tbar[0]/btn[11]`（保存）。
8. 保存后如果仍有 `wnd[1]`：按第 6 步处理，再读 `wnd[0]/sbar`。
9. 结果判定（比 09 更严格，避免把「没变化」误记成成功）：
   - 成功必须同时满足：消息类型 `S`/`W`、文本非空、不含否定关键词、且文本包含 `保存` 或 `saved`；
   - 否定关键词在 09 的列表基础上，10 追加：`未技术完成`、`没有技术完成`、`无法取消`、`未执行`、`not technically completed`、`not possible`、`no change`；
   - `E` / `A` / 空类型 / 无法识别 / 不满足上述任一条件 → 失败；
   - 弹窗消息优先级：弹窗是 `E`/`A` → 失败；否则以 `wnd[0]/sbar` 为准，`sbar` 为空时用弹窗文本；
   - 异常（控件找不到、菜单项不可用、超时等）→ 失败，异常文本作为原因。

补充：

- 第 5 步超时或菜单项不可用时，先尝试读一次 `wnd[0]/sbar`；如果状态栏有内容，用它作为失败原因，比只写 `TimeoutError` 更有诊断价值。
- 已知：非 TECO 的订单，菜单项可能是灰色不可选，`.select()` 会抛异常；也可能能选但保存后提示「未更改」。两种都按失败处理，写 C 列。
- 不做固定秒数等待；需要等待的地方用轮询（`wait_for_control`），轮询间隔 0.5 秒。
- 单笔耗时估计 3–8 秒；58 单大约 3–8 分钟。控制台按单打印进度。
- 「成功消息必须含 `保存`/`saved`」是保守判定：宁可误报失败（B 留空、可重跑），不可误报成功。首次单笔实跑后要核对真实消息；如果公司系统的成功消息不含这两个词，再放宽这一条（这是已知的可调点）。

### 5.1 会话级失败：整轮中止

单笔失败（订单不存在、已锁定、非 TECO、菜单不可用等）只记该单失败，继续下一单。但**会话本身不可用**时不继续，否则剩余每单都要白等两次超时并写一堆无意义的 C 列：

- 判定标准：每单开始时 `wnd[0]` 或 `wnd[0]/tbar[0]/okcd` 找不到；或 `/nIW32` 后连订单号输入框 `ctxtCAUFVD-AUFNR` 都等不到。
- 处理：立即停止整轮，**剩余行完全不动**（不写 B/C），控制台打印「SAP 会话不可用，已中止；第 N 行起未处理」，退出码 `1`。
- 不做「连续失败 N 单就中止」的模糊规则；只有上述会话级信号才整轮中止。

## 6. Sheet 写入

- **成功**：该订单所有待处理行的 B 列写 `Done`，C 列写空字符串（清掉上一次的失败原因）。
- **失败**：B 列保持空；C 列写 `YYYY-MM-DD HH:MM:SS | 原因`。
- 所有写入使用 `RAW`，避免订单号或消息文本被 Sheets 当成公式/数字处理。
- 每单处理完**立即写 Sheet**，不攒到最后：中途 SAP 崩溃或断网时，已完成的结果仍然保留。
- 写入失败重试 3 次（间隔 1 秒、2 秒）；仍失败则记在内存里，整轮结束后再重试一次。
- 整轮结束仍有写不进去的：控制台列出「SAP 已成功但 Sheet 未更新」的订单和行号，退出码 `1`，由用户手工补写。
- 若某单 SAP 成功、但它的 B 列写入最终失败，下次重跑会再次尝试取消 TECO；此时 SAP 会报「未技术完成/未更改」之类的失败并写 C 列。这是已知限制，靠「立即写 + 重试 + 结尾重试」把概率降到最低。

## 7. 控制台与退出码

控制台示例：

```
==== 10 工单取消技术完成 2026-11-03 ====
读到 59 行；已处理(Done) 1 行；待处理 58 单
[10] 5650370（第 2 行）...
[10] 5650370 成功：订单 5650370 已保存
[10] 5655247（第 3 行）...
[10] 5655247 失败：订单 5655247 已锁定
...
==== 完成：成功 55 单，失败 3 单，跳过 1 行 ====
```

- 失败单在每行后面打印原因；最后再汇总一次失败清单，便于直接对照 C 列。
- 不写本地日志文件；C 列就是失败记录。

退出码：

| 退出码 | 含义 |
|---|---|
| `0` | 所有待处理单成功，或没有待处理单 |
| `1` | 任意一单失败、SAP 会话失败、读 Sheet 失败、或结果最终写不进 Sheet |

部分成功也是 `1`，与 09 的约定一致：有失败就让调用方知道。

## 9. 与 09 的关系（重要提醒，写进 README）

- 59 单当前状态都是 `TECO CNF`（2026-11-03 核对）。
- 取消技术完成后，状态回到 `REL CNF`。
- `09` 每天会处理「`REL+CNF`、无 `TECO`，且基本开始日期 ≤ 运行日 - 14 天」的工单，把它们技术完成。
- 这批单大多数基本开始日期在 2026-10-26 之后，目前不会命中 09；但约 1–2 周后会陆续进入 14 天窗口，如果它们届时仍是 `REL CNF`，09 会再次技术完成它们。
- 如果这些单届时应保持未技术完成，需要在 SAP 侧另行处理（例如补工时确认、改日期、或调整 09 的规则）；10 不负责，也无法阻止。
- 10 是一次性工具，跑完保留在仓库即可；不加入 `run_all.ps1`。
